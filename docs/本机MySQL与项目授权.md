# 本机 MySQL 与所选项目授权（0.6.0）

日期：2026-10-26。用户已提供本机数据库连接配置，并明确授权“可在电脑其他位置选择文件夹，但仅限所选文件夹”。

## 本机 MySQL

已验证 127.0.0.1:3306 的服务版本为 MySQL 8.4.13。连接时 ai_project2 不存在，现已按用户给定名称创建为 utf8mb4 空库；当前业务表数量为 0，未导入或生成业务表。

root 仅用于本次初始化。平台继续使用专用本机账号 ai_project2_agent_ro@localhost，随机生成密码，仅授予 ai_project2 的 SELECT，没有全局数据权限、写权限或授权他人的权限。数据库名中的下划线按服务器 partial_revokes 配置处理，避免 GRANT 的数据库通配符扩大权限。已有数据库和其他账号未被修改。

仅专用账号凭证保存在忽略的 .env；root 密码未保存。环境中启用 AI_AGENT_MYSQL_ENABLED=true，并把 mysql_readonly 加到当前演示项目的 MCP 清单。后续登记项目可勾选“使用已配置的 MySQL 只读工具”。工具目标库仍限定为 ai_project2。

验证包括：专用账号连接 ai_project2、SELECT 1、权限清单核对、拒绝读取 mysql.user，以及真实 MCP 连接与数据库 SELECT 检查。没有对业务数据执行写入测试。平台任务与审批记录仍保存于原本的 SQLite，未声称迁移到该业务工具库。

实际记录保存在 .temp/local-mysql-connection-report.json，其中无密码。界面“检查工具连接”能显示地址、专用用户名、目标库及数据库查询成功状态。

官方依据：[MySQL GRANT](https://dev.mysql.com/doc/refman/8.4/en/grant.html)、[账号名称与本机连接](https://dev.mysql.com/doc/refman/8.4/en/account-names.html)。

## 所选文件夹授权

本机通过 .env 的 AI_AGENT_LOCAL_PROJECT_SELECTION=true 启用。默认设置仍为 false；启用后，只有从回环地址访问的本地管理员可以浏览本机磁盘和确认文件夹。模型工具不包含目录授权接口。

“登记项目 → 选择项目文件夹”现在从本机磁盘开始浏览。浏览本身只返回文件夹名称，不把磁盘加入 allowed_roots。用户点击“选择此文件夹”后，后端签发有效期 10 分钟、绑定用户和确切路径的单次选择记录。登记项目时必须校验并消耗该记录，路径被修改、过期、重复使用均拒绝。

Agent 的所有文件工具、检索、图谱、隔离副本及审批写回继续绑定登记项目根目录，不能借选择一个文件夹读取同级目录。拒绝将整个磁盘根目录登记成项目，拒绝网络共享、敏感目录及目录链接。所选目录的实际标识会保存；目录被替换或移动后停止访问，需重新登记。

操作步骤：

1. 在工作台展开“登记项目”，点击“选择项目文件夹”。
2. 进入本机磁盘，找到目标项目，点击“选择此文件夹”。
3. 填写项目名称；按需勾选数据库工具与“允许审批后修改”，点击“登记”。
4. 确认页面显示的读取和写回目录，再提交任务。最终审批后，点击“写入所选项目”才应用修改。

仅手工输入一个范围外路径而没有选择记录，仍不能直接取得访问权限。本轮浏览器验证只浏览磁盘和目录，不替用户选择或授权新的实际业务文件夹；访问边界验证在临时测试目录中进行。
