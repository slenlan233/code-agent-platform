# 项目数据库删除（0.13.0）

## 使用方式

在目标项目的对话中发送：

> 删除当前项目的业务数据库，包括全部表和数据，并清理本地连接配置。保留项目代码。请先展示具体库名和影响范围，等我确认后执行。

也可打开“项目详情 → 业务数据库 → 在对话中申请删除此数据库”，将需求填入当前对话后发送。

仅删库时不生成文件补丁，不运行项目构建。对话直接显示独立确认卡，包含项目、MySQL 地址与端口、完整库名、表数量、可展开的表清单，以及账号和连接配置的处理范围。点击“确认删除这个数据库”后执行，点击“取消删库”则保留数据库。删库无法由文件补丁回滚恢复，确认卡会明确说明。

同时要求清空代码及删除数据库时，先确认文件计划，再单独确认数据库；数据库操作会立即执行，文件补丁仍需验证、AI 检查及具体改动确认。两者不是跨系统事务，过程与结果分别展示。

## 执行边界

- 只接受本机管理员对当前项目平台专属库的删除。目标必须与自动分配的 `agent_app_<项目ID>`、两个项目账号、实例版本和归属记录完全匹配。外部连接库、其他项目库及系统库不能接管删除。
- 模型只能申请 `database_action=drop_project_database`，不能指定任意库名或提交任意删除 SQL。真实目标由后台读取登记记录产生。
- 普通计划审批、文件审批、只读 MCP 或 PowerShell 不能代替独立删库审批。批准请求还必须带上确认卡的完整库名，并受权限策略、取消和预算控制。
- 批准前重新检查实例、分配代次、表清单、账号凭证及完整本地配置的指纹。目标变化、审批过期或来源不属于当前任务时拒绝执行。
- “能不能删库”的普通问题、清空代码、删除表里的数据或删除单张表，不自动转换为删库请求。

## 配置与恢复

成功后删除专属库、两个专属账号和保存的项目凭证；从 `.env` 移除平台连接变量和平台区块标记，保留其他变量、注释及多行值。如果 `.env` 只有平台连接则移除这个空配置文件。原项目代码保留。

平台数据库记录标记为 `deleted`，审计和任务记录保留。后续明确需要业务数据库时可重新准备，使用新的分配代次和凭证；旧审批和已完成操作不能再次删除新创建的数据库。

数据库删除与配置清理分步保存进度。连接中断后，若库已不存在，仅继续清理账号和配置，不重复执行 DROP；如果无法确定首次 DROP 的结果，或者发现库重新出现，则停止并要求核对，绝不自动重复删库。已经实际开始的操作即使原审批后来过期，也只允许恢复清理；不再启动新的 DROP。服务重启会恢复已有有效授权且已进入删除阶段的清理任务，未确认的请求仍停在确认卡。

配置期间有人修改 `.env` 时停止覆盖，保留人工修改并显示部分完成状态。临时清理副本保存在平台私密存储中，不进入模型上下文或工具输出，完成后移除。
