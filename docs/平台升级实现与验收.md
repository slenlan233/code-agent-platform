## 状态与恢复约束

写入任务依次执行 CONTEXT、PLAN、PLAN_APPROVAL、PATCH、VERIFY、REVIEW、DIFF_APPROVAL、SUMMARY。只读和计划模式提前结束，CI Review 不进入写入节点。Docker 不可用时保持等待，不能宣称验证通过；零项 unittest 测试不算通过。

业务表保存任务、审批、工具、证据、产物和反馈，checkpoint 单独保存图执行位置。任务有跨进程租约，应用和回滚还有项目级租约；同机失效进程的租约可恢复。审批 ID 与计划/补丁哈希、当前任务和有效期绑定，恢复时再次验证。应用操作在写文件之前保存稳定日志；崩溃后只接受原始或已写入内容的哈希，拒绝覆盖第三种内容。测试失败把实际日志交给编码 Agent，最多修复两次，仍失败时保留失败节点和测试报告，不进入最终批准。

当前不存在把数据库事务与多个文件替换做成统一事务的机制；依靠逐文件原子替换、持久日志和内容校验恢复。任务中断后需显式恢复，未实现分布式后台队列自动接管。等待审批/环境以外的长时间停机可能触发执行时长预算。

## 证据与知识边界

仓库中的指令、文档和历史会话作为不可信数据进入上下文，不能提升权限。项目规则由管理员配置路径，规则内容有版本与哈希。会话仅复用同项目同用户的结构化摘要，不把模型推断自动升级为长期事实。

知识登记文件 `.agent/knowledge.json` 可提供 `path`、`version`、`status`、`project_id`、`effective_date`、`topic`、`priority`、`rule_id`、`decision` 等元数据；只检索适用、已生效的 active 文档。可选百炼 MCP 接入已有云索引，保存远程来源和版本快照并校验有效期。当前冲突检测针对相同显式 `rule_id` 的相反 `decision`，不是通用自然语言矛盾判定。没有自建向量索引、文档后台同步或长期记忆 TTL 服务；百炼云端检索仍需真实账号和索引联调。

Java 图谱只覆盖可解析的静态调用、简单接收者类型及 MyBatis XML 表关系。反射、动态代理、复杂泛型/重载等保留为未知；查询结果 `complete=false`，后端标记 `local_poc`。不应把该图谱当作完整影响证明。

敏感路径和常见凭证模式会阻止模型读取与返回；这不是覆盖所有密钥格式的 DLP 系统。已将当前源码中的模型/云凭证改为环境变量；历史压缩包保留，旧凭证未代为轮换。
