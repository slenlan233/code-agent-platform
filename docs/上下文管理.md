# 渐进式上下文管理（简化版）

版本：0.16.2｜日期：2026-10-27

## 目标与边界

本实现借鉴先做低成本处理、再做模型摘要的思路，不声称复现 Claude Code 的内部四级机制，也不依赖某个供应商的缓存过期时间或 cache editing API。

当前使用 LangChain AgentMiddleware 管理模型的请求视图。UI 聊天记录、工具审计和原始结果保留在平台存储中；改变发送给模型的上下文，不等于删除历史记录。LangChain 官方也提供按 token 或消息阈值触发的摘要中间件，本项目增加了审批保护、用量审计和工具结果读回约束。[LangChain 摘要机制](https://docs.langchain.com/oss/python/langchain/middleware/built-in#summarization)

## 三步处理

1. **初始阶段材料选择与可读回归档**：普通阶段材料预算为 18 万字符，编码阶段按输出额度提高，当前 128K 输出对应 393,216 字符；与活动历史的 token 阈值分开。保留本轮需求、项目规则、完整计划范围、当前批次代码、最近对话和当前失败信息。根据当前代码中的类型、导入和文件名识别关联提示，先归档无关的大材料；仅在仍然超额时才归档关联材料。归档前保存完整的已提供原文，再提供带原始行号的接口/相关行预览及 artifact_id，使用 `read_tool_result` 分页读回。没有归档能力时拒绝丢弃正文。必要材料仍超过预算时明确停止，多文件编码批次会自动拆小，不强行截短。这是启发式相关性选择，不是完整语义依赖图，也不保证模型永远无需重读。
2. **旧工具结果归档**：当活动请求估算达到 48,000 token，较早的大段文件读取、检索和 MCP 只读结果被替换为带预览、来源编号和 artifact_id 的标记。最近六个工具结果保留。模型可以调用 `read_tool_result` 分段读回，读回时重新检查任务归属、原工具授权、来源路径和连接身份。
3. **完整轮次摘要**：归档后仍达到 96,000 token，且累计新增至少 4,096 个估算 token 的可压缩历史，才使用无工具的模型调用摘要较早的完整调用轮次。保留第一条含当前任务与审批上下文的消息、最新用户补充指令及最近至少八条消息；不拆开一次并行工具调用与其全部结果。摘要缓存复用，避免对同一段历史反复收费；生成后没有实际缩短请求的摘要会被弃用，等待足够的新历史再尝试。

第一步发生在每个规划/编码/审查阶段的材料包组装时，不是先删旧聊天。活动历史的顺序始终是：估算 → 可读回归档旧工具结果 → 重算 → 必要时摘要。两个层次都先保存原文，减少模型请求中的重复正文；不存在先永久丢掉重要代码再压缩的处理。

阈值是操作预算，不是模型实际窗口大小。当前 DeepSeek Flash 官方窗口为 1M；本平台预留输出空间，并可更早整理输入以控制成本。[DeepSeek 模型信息](https://api-docs.deepseek.com/quick_start/pricing/)

## 预算和估算

估算包含可见消息、工具调用参数、DeepSeek reasoning_content、系统消息和工具定义，使用 UTF-8 字节数除以三的近似方法，不是 DeepSeek 精确分词。真正计费仍采用供应商返回的 input/output/cache token；不能把累计 token 当作当前上下文。

窗口检查从当前模型请求读取输出上限：编码/返修预留 131,072 token，问答/规划/审查等通常预留 32,768 token，截断后的重试会重新按 65,536 token 预留。不会把旧兼容配置中的 16K 用作所有请求的预留值；界面显示最近一次实际预留额度。

摘要调用复用已有用量审计机制，记录为 `context_summarizer`，计入本轮模型次数、token 和成本预算。默认 4K 输出，截断后使用相同输入重试一次到 8K，两次调用分别计量且都检查剩余预算；重试前重新核对输入加输出预留是否能放入窗口。提示词目标约 2,400 字符，优先保留用户约束、来源编号与未完成事项，不再机械限制为 800 字。DeepSeek 摘要调用关闭思考模式、不给工具；不是启动一个能修改项目的子 Agent。最终失败或仍被截断时保留原历史，不接受不完整摘要。

压缩会改变请求前缀，可能降低缓存命中；摘要也有额外用量。它优先控制上下文规模，不保证每一次都降低总费用，阈值应结合实际任务和缓存记录调整。

## 权限和信息保留

- 执行权限仍由后端计划、文件基线、Diff、审批记录及网关决定，摘要不会提供新授权。
- 读回允许本任务明确登记的归档材料，以及当前补丁验证记录绑定的 stdout/stderr 和当前计划绑定的命令输出。不能传入其他任务、旧补丁验证日志或任意内部产物的 artifact_id。读取时重新核对任务/补丁/计划归属、策略、文件路径、来源授权、MCP 连接身份和产物哈希。
- 旧工具结果是历史快照，不自动等价于当前代码事实。原始文件、远程来源变化仍要验证。
- DeepSeek 工具调用消息保留原有 reasoning_content；摘要作为独立文本消息，使用空 reasoning_content，旧完整调用组才可被替换。
- 当前跨轮对话仍使用最近四轮和任务摘要；此功能主要管理单轮 Agent 的活动工具循环，不是无限长对话记忆。完整早期消息仍可在 UI 回看。

## 配置

管理员可在 `agent-config.local.json` 中设置以下可选部分；省略时使用这些默认值：

```json
{
  "context_management": {
    "enabled": true,
    "tool_result_trigger_tokens": 48000,
    "summary_trigger_tokens": 96000,
    "context_window_tokens": 1048576,
    "keep_recent_tool_results": 6,
    "keep_recent_messages": 8,
    "minimum_tool_characters": 3000,
    "minimum_summary_tokens": 4096,
    "summary_max_tokens": 4096,
    "summary_retry_max_tokens": 8192,
    "summary_target_characters": 2400
  }
}
```

其他模型的窗口应按实际规格设置。压缩配置单独记录 hash，不改变已批准的文件和数据库范围，因此调整性能阈值不会使未变化的 Diff 失效；每次模型调用仍记录所用上下文配置版本。

## 检查入口

任务详情的 `context_usage` 保存最近一次请求压缩前后的估算量。执行事件包含 `ContextCompacted`、`ContextToolResultsArchived`、`ContextSummarized`；原始 token 用量保留在模型调用记录中。

除本地回归外，应验证一次真实摘要调用，确认额外用量被统计。当前实现不提供 Claude 专属 Snip 命令、缓存编辑、后台折叠任务或无限长期记忆。

## 审批过期恢复

过期审批不会自动延长。继续原任务时，先核对同一计划的范围、代码基线和来源，再重新展示原计划供人工确认；保留已经生成的分批提案与原审批历史。避免出现审批已经失效但界面仍显示“执行中”的状态。

工作台可用 `scripts/start-workbench.ps1 -Restart -NoBrowser` 重启。脚本检查实际端口监听进程的身份后停止，避免虚拟环境启动器退出后仅停止父 PID、实际旧服务仍驻留。
