# 会话与运行稳定性

版本：0.17.0｜日期：2026-10-27

## 重试与跨轮记忆

新任务保存创建时已有的前序任务 ID；老数据以创建时间和 ID 排序确定边界。重试旧轮不能读取后续轮次，阶段材料中的 session_summary 也遵守该边界。首次检索生成本轮历史快照，后续重试沿用；当前代码、数据库和远程引用仍重新检查，历史快照不替代新鲜证据。

最近 4 轮保留用户完整输入、助手回复片段及执行状态。更早的历史用确定性记忆整理，保留最初目标（最多 4000 字符）、带原任务 ID 的用户约束摘录（合计最多 8000 字符），以及最近 24 个旧轮次的索引。没有用 LLM 推测用户意图，冲突仍以本轮明确要求为准，未明确时澄清。

全部前序轮次的用户输入、公开回复及当时交付/测试状态，另存为本轮专属的 JSONL 历史归档，可用 read_tool_result 按字符分页读回。旧 source_id 是历史引文，不能作为本轮代码事实或权限；平台为仍需使用的历史用户约定重新建立本轮 request 来源，校验其原消息、会话、时间边界和哈希。其他会话、未来轮次和未绑定的伪造归档仍被拒绝。

这是一版有界的跨轮记忆，不是无限记忆。执行中的旧工具结果归档与模型摘要保持独立，必要材料仍须读回，不能保证所有历史细节都在每次请求中自动出现。

## 停止与资源清理

正在执行的任务先进入“正在停止”，该会话暂不能发起另一轮；模型请求通过可取消的异步网络调用中断，Docker/PowerShell 测试循环检查停止状态，MySQL 测试启动阶段也检查停止并清理临时环境。清理结束后才显示“已停止”。普通同步 Docker 管理命令和其他同步工具可能需要等当前命令返回或各自超时。

运行容器附加 owner 和 task 标签。重启后发现未完成的停止任务时，后台仅核验、清理本任务且 owner 匹配的测试资源；不删除用户已有容器。Docker 不可用或清理失败会保留清理警告，不把未核实的资源说成已经清理。

停止不撤销已经完成的写入、迁移或删库，也不能保证供应商停止计费。中断请求可能拿不到 token 回执，模型记录标记 interrupted_unknown；项目用量提示当前只累计已收到的 token，实际账单以供应商为准。

## 知识服务路由与降级

必需服务（MCP required=true）仍必须可用，不能跳过项目规范。可选百炼预检使用保守的低成本规则：短确认、问候和纯本地启动问题可以跳过；明确知识库/规范请求会查询；不确定的开发需求仍查询。模型也可通过已授权的检索工具按需查询。这不是完整的语义路由模型。

可选服务连接失败或查询超时等服务故障，会留下可见提示，本轮只使用已有本地依据。平台权限拒绝、来源篡改、配置变化、任务取消、额度超限等不会当成可降级故障。失效引用的刷新规则保持不变。

## 验收范围

离线 eval 继续验证固定流程与权限，不统计为模型准确率。新增 eval --engine model --repeats N，在平台数据目录内建立独立 Python/Java 仓库，运行真实模型问答、计划和多轮记忆，记录各项断言、错误分类、用量和耗时。数据目录必须处于管理员允许的根目录内。

真实模型验收不自动批准写入，不操作用户现有项目、业务库或外部服务。其结果是固定场景通过率，不是通用模型能力、生产成功率，也不能替代真实项目的生成、Docker/MySQL 集成测试和人工验收。AI 代码检查仍绑定具体补丁；“通过”不等于代码绝无缺陷。                                             

本机验证：首轮 310 项全量回归通过；补齐历史引文读取、因果引用校验和重启清理后，146 项相关回归通过，最后的完成状态检查又通过 23 项基础工作流回归。真实 DeepSeek 首次验收为 7/8，暴露的历史归档读回问题修复后，新一轮 8/8 通过；两份报告分别保留在 `.temp/reliability-model-report.json` 与 `.temp/reliability-model-report-fixed.json`。本机 Docker 临时容器停止耗时 375ms，资源清理核验通过，记录为 `.temp/reliability-docker-cancel-proof.json`。这些都是本次本机测试记录。
