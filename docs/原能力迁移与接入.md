# 原能力迁移与接入（0.3.0）

本轮遵循两份文档指定的分工：LangGraph 负责外层任务状态、审批、验证和恢复，LangChain 负责内部 Agent、模型和工具调用，MCP 提供工具协议接口，后端网关执行权限和审计。优先复用原实现；与项目范围、隔离和审批冲突的旧执行入口不直接迁入。

## 真正连接 MCP 的调用链

`LangGraph 业务节点 → 共享 LangChain Agent → 网关工具 → MCPRuntime → 每任务/每服务独立会话 → MCP Server → 原工具函数`。

默认项目配置包含 `project_files`。创建真实模型 Agent 时会发现、筛选和绑定该任务获准的工具；演示引擎不需要模型，不自动调用这些外部工具。每个 MCP 会话由同一个异步任务打开、调用和关闭，避免将持久 ClientSession 在不同临时事件循环之间传递。一次任务运行结束、进入审批等待或平台关闭时回收会话与 stdio 子进程，恢复后重新建立只读工具连接。

支持本地 stdio 和远程 Streamable HTTP。自定义 Server 由管理员在平台配置中登记启动方式、只读属性、允许工具、参数路径字段、超时、环境变量名或认证头对应的环境变量名；项目再选择可用配置。仓库文本和模型不能注册 Server、指定启动命令或提升工具权限。

平台不会自动继承完整宿主机环境，也不会把旧 Server 的全部工具一次性暴露给模型。用户身份、项目和任务由网关绑定；MCP 工具参数按 JSON Schema 校验，未知参数、路径越界、撤销的工具授权均被拦截并记入审计。远程只读属性仍依赖管理员审查服务实现和服务端权限，声明本身不能把任意程序变成只读程序。

## 使用方法

在平台配置中启用需要的内置配置，参考 `agent-config.example.json`。配置只写环境变量名，不写凭证值。自定义 stdio 示例：

```json
{
  "mcp_servers": {
    "internal_docs": {
      "transport": "stdio",
      "command": "python",
      "args": ["D:/approved-tools/docs_server.py"],
      "allow_tools": ["search_docs"],
      "env_keys": ["INTERNAL_DOCS_TOKEN"],
      "required": false,
      "read_only": true,
      "timeout_seconds": 20
    }
  }
}
```

HTTP 配置使用 `transport: "http"`、`url: "https://approved-service/mcp"`，可用 `headers_env: {"Authorization": "INTERNAL_MCP_AUTHORIZATION"}` 指向完整认证头的环境变量。地址不能内嵌账号、密码或查询参数。配置和服务实现应由管理员信任，不能由模型或仓库文件提供。

登记和检查：

```powershell
uv run --no-sync ai-agent --config agent-config.local.json project-add "项目目录" --name 项目名 --mcp-server project_files --mcp-server bailian
uv run --no-sync ai-agent --config agent-config.local.json tools --project 项目ID
uv run --no-sync ai-agent --config agent-config.local.json project-config --project 项目ID --file project-config.local.json
```

`project-config.local.json` 参考 `project-config.example.json`，可以更新 MCP 配置清单、测试参数列表和镜像。更新会递增项目配置版本，使旧计划审批重新检查。网页提供“检查工具连接”，保存无模型调用的连接检查记录；这些记录不计入模型任务成功指标。

## 百炼接入

配置 `.env` 中的 `ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET`、`BAILIAN_WORKSPACE_ID`、`BAILIAN_INDEX_ID`，在管理员配置中启用 `bailian`，并加入对应项目的 `mcp_servers`。

上下文检索阶段会调用已启用的百炼查询，再与本地检索依据一起进入计划或问答。返回结果保留文档 ID、标题、版本和内容快照；过滤 archived、尚未生效和明确属于其他项目的文档。缺少远程版本时使用文本哈希，并明确不能替代源知识库版本管理。

远程证据绑定当前任务、项目、连接配置和有效期，内容快照存为 artifact。引用校验检查快照完整性、有效期和连接范围，不宣称能离线验证远程源文档仍然最新。只读查询不会获得上传工具；原上传实现只保留在显式管理入口，并限制项目文件范围和内容。

百炼本轮通过 SDK 返回契约和过滤/引用测试，未用用户云账号开展付费/真实云端联调。实际使用仍需有效配置、已有索引和业务验收数据。

## MySQL 接入

配置 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_READ_USER`、`MYSQL_READ_PASSWORD` 和逗号分隔的 `MYSQL_DATABASES`，启用 `mysql_readonly` 并加入项目。账号应由数据库管理员授予登记库的 SELECT 权限，平台默认账号名为 `agent_reader`，拒绝使用 root。

原查询工具现在同时受到工具白名单、SQL AST 校验、数据库范围和数据库权限限制；只允许受限的单条 SELECT，拦截写入、多语句、锁及危险/未知函数。连接设置只读事务和 MySQL 查询时限，结果限制 200 行。只有部分值参数化不能替代表/字段标识符校验，新的表结构查询已校验标识符。

数据库管理函数仍保留供兼容代码使用，但默认不注册，平台子进程也不会继承管理启用开关。当前只读执行设置针对 MySQL，未承诺兼容所有 MariaDB 版本。

## 本轮验证与边界

- 真实 stdio MCP：文件读取、来源摘要、路径/参数拦截、独立任务会话、连续调用状态与子进程回收。
