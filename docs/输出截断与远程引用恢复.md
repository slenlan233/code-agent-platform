# 输出截断与远程引用恢复

版本：0.16.2｜日期：2026-10-27

## 本次故障证据

AgentTodo 的第四轮开发请求在代码生成阶段失败。日志中的单次输入约为 1.7 万至 5 万 token；界面的百余万 token 是多个阶段与重试的累计量，并非一次模型请求的上下文长度。

四次代码生成响应输出约 16,384 token，并以 `finish_reason=length` 结束。直接原因是一次返回多个完整文件超过单次输出上限。原流程将截断误归类为“没有提交结构化结果”，并把不完整结果追加进重试消息，导致重复超限。仅凭这些记录不能归因为模型能力不足或上下文注意力下降。

## 代码生成修复

- 按 `finish_reason` 识别截断，记录 `output_truncated`，不将截断内容追加为同样大小的重试。
- 工作台已启用分阶段额度：编码/返修 131,072 token、请求超时 600 秒；问答/计划/审查/最终回复默认 32,768 token、180 秒，明确发生输出截断时自动放宽到 65,536 token、300 秒，同一阶段最多放宽一次。
- 上下文摘要默认 4,096 token，截断时最多重试一次到 8,192 token。提示词改为约 2,400 字符的目标，优先保留约束、待办与来源编号，不再要求压到 800 字。摘要字符防御校验随配置调整；只有完整、实际缩短上下文的摘要才会替换请求视图。
- 编码批次按已知代码体积、文件类型和输出预算估算，默认最多八个文件，预留一半输出空间给推理和结构化封装。大文件减少批量；估算不是模型精确 tokenizer，也不保证不会截断。
- 发生输出截断、阶段材料预算超限或上下文窗口不足时，多文件批次按预计体积分成两批继续；单文件仍超限时明确停止并保留前面批次。未启用新生成配置的旧安装保留三文件策略。
- 每批通过结构、范围与凭证检查后保存到平台提案记录；同一生成阶段重试时续用已完成批次，不重新生成全部文件。测试或 AI 检查进入新的返修阶段时，不复用旧阶段缓存。
- 提案合并后仍经过完整测试、检查及最终接受流程；分批提案不是直接写入项目。

### 生效配置

工作台使用 `agent-config.local.json` 的 `generation`，示例见 `agent-config.example.json`。存在该配置时，按阶段覆盖请求中的 `max_tokens` 和 `timeout`；旧 `model_max_output_tokens` 仅在没有 `generation` 时回退使用，不会再把新编码请求压回旧的 16K。

每次模型调用记录真实采用的输出上限、超时和生成配置哈希；模型交互详情展示这两个值。上下文窗口检查也按该次调用实际额度预留空间。生成额度、批次调整不改变文件/数据库审批范围，单独记录配置版本；现有已完成批次在同一提案阶段继续复用，测试或审查要求的新返修阶段仍按新生成键执行。

普通阶段的额度重试复用截断前的请求，保留完整工具调用及结果，不把半截回复加入历史，也不先执行半截回复中的工具。摘要重试使用相同输入。每一次调用都单独检查模型次数和 token 预算、记录供应商用量；更高额度仍不足时明确停止，保留原始记录，不继续无限放宽。

编码阶段的初始材料字符预算同时提高到 `max(180000, 单次输出额度×3)`；当前为 393,216 字符，避免大文件在获得 128K 输出额度后仍被旧 18 万字符门槛提前阻断。该字符预算不代替最终的模型窗口估算，仍会预留实际输出额度并检查总窗口；多文件材料放不下时自动拆批。

## 上下文处理范围

已有对话采用最近四轮、每条长度受限的历史视图，并未将全部聊天和累计 token 原样发送给模型。

初始阶段材料采用完整原文归档、依赖提示排序和定位片段，不再只截取前几百字。规则、需求、批准范围、当前批次及当前失败信息不归档。活动工具循环则先归档旧工具结果，空间仍不足才进行 LLM 摘要，详见[上下文管理](上下文管理.md)。

## 远程引用恢复

百炼引用保留原检索参数。来源到期时，通过当前权限和真实 MCP 再次执行检索；旧引用再次命中且内容 hash、连接绑定均未改变，才更新其有效期。

旧版本引用可从原工具审计记录恢复检索参数。原内容未命中、内容变化、快照损坏或连接绑定变化时，不静默续用原审批依据。百炼检索仍可能因为 top-K 未返回原片段而保守停止，不将未命中当成内容未变。

MySQL 观察结果也保存原工具和查询参数。过期后只允许重放内置的列库、列表、描述表结构及受 SQL 策略检查的单条 SELECT；每次通过当前网关授权、预算和审计。结果必须成功且完整内容哈希一致，才能续期。行数据/结构变化、查询失败、账号/连接或权限变化都会停止；新结果不能替代旧审批依据。未知第三方 MCP 工具、数据库写入/迁移/删库等操作不自动重放。查询结果的行顺序或动态字段变化也可能触发保守拒绝。

这保留了来源有效性校验，同时避免仅仅等待超过 15 分钟就让未变化的知识库依据永久卡住重试。

## 审批时限与页面恢复

默认有效期保持 3600 秒，可由管理员配置 `approval_seconds`（1～86400 秒）。待确认页面有有效期；人工批准后的执行授权从实际点击批准时重新计时，不从页面生成时扣减。

- 待确认页面过期时，对话正文直接显示“上次审批时限已到，请重新审批”，提供“刷新原审批内容”。刷新只在基线、来源和必要检查仍一致时重新展示相同内容，不等于同意执行。随后需要重新点击确认。
- 已批准的执行授权在执行节点过期时，自动暂停并重新显示原审批卡，保存生成批次和补丁，不需要先点“重试本轮”。决策历史保留，未重新批准前不执行。
- 接受 Diff 后尚未开始写入而授权过期，也回到相同 Diff 的人工确认，不重新生成代码，不重置部分写入日志。
- 页面轮询包含后端计算的过期状态；计划、文件改动和删库确认都有过期提示。采用对话内可见审批卡，不强制弹出遮挡聊天的模态窗口。
- 人工等待时间不计入执行时长预算；续期后的新等待单独统计。来源刷新与审批续期是两个独立动作。
- 每次续期增加审批决策版本；确认请求必须携带新版本。旧页面或上次确认的请求不能在续期后重放成新的批准。

## 返修日志与旧等待统计修复（0.16.2）

新一轮 Todo 任务已经生成 14 文件提案，隔离测试运行 26 项、失败 1 项。Maven 标准输出约 65KB，返修上下文原本只包含前 12KB，但仍暴露了完整 stdout_id。模型使用 read_tool_result 读取该 ID 时，它不属于旧工具归档类型，因此被拒绝并中断。

现在按当前验证记录和补丁核对 stdout/stderr 归属，允许通过同一读回工具分页读取；当前计划的已批准命令输出同样按执行回执绑定。跨任务、旧补丁和未登记的内部产物继续拒绝。日志仍执行当前策略和哈希检查。返修上下文从 task.verification.id 精确取得对应测试，提供首尾预览和完整日志读法，不再依赖列表最后一项或只给启动日志。

旧一轮的 pending 审批历史保留了上一轮 reviewer/decided_at，且 counted_approvals 使用相同审批 ID 去重，导致续期时漏扣长期待审批时间。现在改按审批 ID、waiting_since 和决策版本区分等待窗口。兼容校正仅处理具有该旧版本特征的窗口，扣除已统计的失败暂停重叠，并保存校正键防止重复扣减；不清零实际执行耗时、不增加执行预算，不改变审批结论或补丁内容。

## 验证

定向回归覆盖：截断分类、批次拆分、断点续跑、新返修阶段重新生成、上下文预算、旧引用兼容刷新、内容变化拒绝、连接变化拒绝，以及既有 MCP 和审批交付流程。
