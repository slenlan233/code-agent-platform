# 权限策略与运行钩子

平台使用 LangGraph 管理阶段，用共享的 LangChain Agent 工厂运行规划、编码和审查；权限、审批和 Hook 由后端执行，模型输出与仓库内指令不能授予权限。

## 分层限制策略

管理员配置 `agent-config.local.json` 的 `policy_rules`、`team_policies`、`user_policies`，分别对应企业、团队、用户层。项目登记/更新的 `team`、`policy_rules` 对应项目层。创建会话的首个任务把输入 `policy_rules` 保存为会话规则；同一会话后续任务可在任务层增加限制。

匹配层包括 enterprise、team、project、user、session、task；任何层的 deny 优先于 ask，ask 优先于 allow。allow 不能越过角色、项目访问范围、只读模式、工具白名单或既有审批，也不能抵消上层 deny。策略支持工具名、路径 glob、mode、user、role 条件；不支持任意代码表达式。路径使用项目内规范化相对路径，按 Windows 不区分大小写比较。

```json
{
  "policy_rules": [
    {"rule_id": "protect-private", "effect": "deny", "tools": ["read_file"], "paths": ["docs/private/**"]},
    {"rule_id": "protect-deploy", "effect": "deny", "tools": ["apply_patch"], "paths": ["deploy/**"]},
    {"rule_id": "review-changes", "effect": "ask", "tools": ["apply_patch", "run_tests", "export_patch"]}
  ],
  "team_policies": {},
  "user_policies": {}
}
```

ask 当前复用计划和最终 Diff 两次审批，支持 `apply_patch`、`run_tests`、`export_patch`、`run_powershell`；配置其他 ask 工具会报错，尚未实现通用的逐次读取审批界面。PowerShell 还会核对完整脚本和超时与已批准计划完全一致。读取默认受平台只读规则约束，额外限制用 deny。原文件 MCP 的别名归一到 read_file/list_files，同样受策略限制。搜索、RAG、Git 输出与图谱查询也按来源文件过滤，不因提前建立索引而继续返回已禁止内容。

每次工具调用重新取得身份和项目权限，保存实际策略匹配结果。任务恢复校验项目配置版本与会话/任务规则摘要；批准范围或基线改变后不能沿用旧审批。API 用户不能使用保留的本地管理员 ID，也不能为同一用户配置互相冲突的角色。

## Hook 执行

`platform.gateway.hooks` 提供受信任服务端 Python 回调注册，包含 UserPromptSubmit、SessionStart、BeforePlan、AfterPlan、PreToolUse、PostToolUse、BeforeFileEdit、AfterFileEdit、BeforeCommand、AfterCommand、AfterTest、BeforeCommit、TaskCompleted、SessionEnd。BeforeCommit 是扩展点；当前没有自动提交仓库的行为。SessionStart/End 记录一次工作流运行片段，审批暂停和恢复会产生不同片段，不等同用户登录会话生命周期。

```python
def check_before_command(actor, task, payload):
    return payload["command"] == ["python", "-m", "unittest", "discover", "-s", "tests"]

platform.gateway.hooks["BeforeCommand"].append(check_before_command)
```

普通 Hook 接收 `(actor, task, payload)`；兼容原工具回调的 PreToolUse/PostToolUse 接收 `(actor, task, name, arguments_or_result)`。payload 深拷贝后交给回调，不能借修改参数改变已批准的操作。返回 False 或抛错阻止流程，记录 HookExecuted 的状态、回调数量和耗时。结束钩子失败也不会把任务报告为成功。

内建 AfterTest 检查通过报告具有退出码 0；写任务完成前检查测试通过与最终 Diff 已批准。测试失败后读取实际 stdout/stderr 交给编码 Agent，最多两次修复；不得跳过测试、减少既有断言或绕过批准文件范围。格式化、lint 与业务规则检查需要由管理员接入具体规则，平台未把这些项目规则假称为已配置。

不从项目仓库自动加载并执行 Hook 脚本，不给模型宿主机 Shell；命令仍由批准的测试参数列表在隔离容器内执行。多进程应用和回滚同时取得项目级数据库租约，避免两个任务同时覆盖同一个项目。
