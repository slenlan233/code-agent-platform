# 连续对话、业务数据库与人工确认

本轮在原项目上继续修改。Agent 仍使用共享的 LangChain Agent 和工具，LangGraph 负责有状态的任务控制；项目、会话及历史任务沿用原有存储。

## 0.12.0 引用补正与额度选择

模型返回计划或问答后，平台先检查引用是否遗漏或使用了本轮不存在的编号。若不合格，将校验错误和本轮真实来源交给同一 Agent 自动补正，最多两次；补正也计入本轮模型用量，并受预算与取消限制。仍不合格才报告失败，既有文件 hash、来源范围和权限检查保持生效。规划可引用本轮用户需求，用户日志也可作为回答依据；这些不表示已存在源码或规范文件。平台不会替模型编造引用或把所有读过的文件自动当成其结论依据。

项目 Token 仍可选择 100 万、200 万（默认）、500 万、1000 万、5000 万或自定义数量。自定义不再受 5000 万限制，另有主动选择的“无上限”，通过 API 的 `null` 表示；不传预算字段则保留现值。既有项目额度不自动变更。无上限项目依然显示输入、缓存、输出和累计用量；有限的显式单轮额度继续生效。

用户于 2026-10-26 明确授权覆盖此前保留全局默认值的限制：新轮次默认模型 60 次、工具 200 次、工作流 200 步、执行 3600 秒。每条用户消息对应一轮任务，规划、返修、检查和总结共用这些额度；新消息重新计数，同轮审批或恢复不清零。旧任务保留自己的执行额度。两次引用补正不是无限重试；测试和 AI 检查的返修次数仍有独立边界。

预算与引用检查的回归结果见 `.temp/unlimited-budget-tests.log`、`.temp/citation-auto-repair-tests.log`。完整回归 192 项通过，见 `.temp/platform-v012-full-tests.log`。

## 0.11.0 对话与保存更新

0.11.1 修复“先给计划，等待我确认后执行”被模型误选为只生成计划的问题：模型仍先规划，平台把明确的确认后实施意图接到未批准的计划节点，用户点“确认并开始”后，同一轮自动继续生成、测试和 AI 检查。显式的只生成计划模式及只读项目保持原有限制。计划确认卡直接展示目标、步骤、验证方式和文件范围，较长内容可独立滚动，完整计划仍可在侧栏查看。误分类复现、审批后继续及既有交付流程 18 项检查通过，会话兼容检查 11 项通过，见 `.temp/plan-approval-regression.log`、`.temp/plan-conversation-regression.log`。

网页默认“自动处理（修改需审批）”。后端先以只读能力理解当前消息：普通提问直接读取项目资料并回答，不生成计划或补丁；明确要求修改才生成精确计划并等待审批。“只读问答”“只生成计划”“审查变更”仍可手动选择。旧网页的“审批后修改”消息按自动处理解释，避免把“怎么运行”强制转成修改任务；显式的旧任务 API 语义保持兼容。

最终按钮为“接受并写入项目”：请求中明确绑定写入意图，执行结束后自动保存对应的、已经通过测试和 AI 检查的补丁。既有的文件范围、审批哈希、基线变化和权限检查继续生效；失败会显示保存错误并保留重试入口。旧审批没有写入意图，不会被追溯自动应用。程序显示的实际保存状态优先于早先模型总结中的状态措辞，原模型输出仍保留在审计记录中。

模型工作 Agent 不继承外层任务的内部消息检查点，避免恢复父节点时复用过时的结构化结果；外层任务仍持久化恢复，公开模型消息仍独立保存。返修读取上一版补丁的文件，并将局部修复合并到完整补丁，保留未修改的新文件。

## 项目如何找到数据库

本机 MySQL 实例在“项目详情 → 业务数据库 → 本机 MySQL 实例”配置一次。当前本地预览已校验用户提供的 127.0.0.1:3306 / MySQL 8.4.13。既有管理账号的凭证通过 Windows DPAPI 加密保存在平台数据目录的 `secrets/` 中，不写进业务表、模型上下文或审计记录。

添加允许修改的 Java + MySQL 项目时，后台创建该项目专属的永久库和两个账号。其他项目在模型计划中标记 `requires_database=true` 后，确认实施范围时自动准备。账号仅获得该项目数据库权限：业务账号为增删改查，迁移账号另有建表、修改表和索引等权限。管理连接只由后台调用，模型不能拿它执行任意 SQL。

模型的可信上下文自动包含 `business_database`：是否就绪、库名和连接配置的使用约定。新建项目的用户提示词无需包含地址或密码。后台在所选项目的 `.env` 中注入 `APP_JDBC_URL`、`APP_DB_USER`、`APP_DB_PASSWORD`、`MIGRATION_DB_USER`、`MIGRATION_DB_PASSWORD`；模型只能看到变量名称。生成的程序和启动脚本需要读取这些变量。原来的完整 `.env` 连接会沿用，部分配置会提示补齐，不会覆盖用户已有连接。

“MySQL 只读查询工具”是供模型查看被授权库内容的可选 MCP 能力，和业务程序运行时读写数据库是两回事。未启用它不会阻止业务程序使用平台准备的业务库。业务库在任务结束后保留；Docker 集成测试继续用独立的临时库，不触碰业务数据。禁用项目也不会自动删除业务库。

管理实例改变后，既有项目保持原连接；新项目使用新配置。备份或迁移平台时需要同时保留本地加密凭证及项目 `.env`。Windows 加密凭证绑定当前用户，不能直接复制到其他用户下解密。

## 每轮聊天如何展示

主聊天区每轮仅展示用户消息、一条默认收起的处理过程，以及执行结束后的助手最终答复。点击左侧图标或整条过程栏，可展开实施计划、工具调用、测试、AI 检查和已处理的确认记录。过程区限制高度并独立滚动；完整 Diff、报告、依据和用量在详情侧栏查看。

需要用户操作时，确认卡立即在折叠栏外显示：

- **确认实施范围**：允许生成补丁、运行已声明的命令和测试，必要时准备项目数据库。
- **AI 代码检查**：模型读取实际补丁副本后给出问题及依据；这是自动检查，不是人工审批。
- **等待你确认改动**：实际测试和 AI 检查通过后，用户查看具体修改并决定是否接受。
- **接受并写入项目**：0.11.0 起，最终确认即保存该份具体补丁，界面显示保存中、已保存或保存失败；旧任务仍兼容原来的独立写入动作。

AI 检查有阻断问题会回到修改节点，带上先前补丁和检查问题，再测试、再检查。连续三次阻断后本轮失败并保留记录，不进入最终人工确认。确认、导出及写回会校验检查结果是否匹配当前补丁；过期或更换补丁的检查结果不可复用。历史任务按原记录兼容展示。

“处理过程”展示公开计划、操作和结果，不保存或展示模型内部推理内容。问答模式直接返回回答；计划模式不执行修改。模式选择仍由输入框旁的选项控制。

## 验证

0.10.0 补充项目 Token 预算：添加项目时可选择 100 万、200 万（默认）、500 万、1000 万、5000 万或自定义 100—5000 万 token。该额度合计项目内全部会话和任务的供应商报告输入与输出，缓存属于输入的一部分。额度不是上下文窗口大小，也不是一次性购买或发送数量。

新建聊天轮次默认跟随项目总预算；显式 API 单轮预算仍可额外设置更小的限制。修改预算与修改代码权限分别记录，不使已经批准的文件范围失效，不清空既有用量。旧的单轮 10 万额度任务可以在侧栏选择“保存并继续本轮”，切换为项目预算后从原节点恢复。时间、工具和模型调用次数的限制继续生效。

全局默认仍是每轮最多 12 次模型调用、30 次工具调用和 600 秒执行时间；提高项目 token 额度不会自动提高这些限制。当前 `AgentTodo` 项目已按用户授权调整为 5000 万 token，原有用量保留。若单轮其他限制耗尽，继续前需要另行确认该轮的具体额度。

预算根据供应商实际报告在每次模型/工具调用前后检查。正在进行的一次模型调用可能使最终统计超过额度，达到额度后会阻止后续调用。项目默认 200 万是试用起点，实际需要多少取决于项目规模、上下文长度、返修和对话次数。
