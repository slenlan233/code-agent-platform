# 项目与对话归档（0.14.0）

## 入口与行为

- 工作项目和每条对话右侧新增“⋯”，可选择归档或删除。
- 左下角新增“归档”，打开后有“归档项目”“归档对话”“回收站”三个分类，支持搜索。
- 项目归档后从工作项目列表移除；可以展开查看其中的对话、历史消息和处理记录，恢复后回到工作项目列表。
- 对话归档后从项目的正常对话列表移除；恢复后保持原会话 ID、消息、任务及用量，可以继续对话。
- 删除先移入回收站，可查看和恢复。删除确认明确说明这是工作台记录操作，本机项目文件夹和数据库保留。当前不提供清空回收站或永久销毁历史的入口。
- 归档中的记录被删除后，恢复会回到原归档位置；按钮显示“恢复到归档”。恢复项目不会擅自取消其中对话各自的归档或删除状态。

## 范围与持久化

项目和会话记录增加持久化 `lifecycle=active/archived/deleted`；旧记录没有该字段时继续按 active 使用。原 enabled 管理开关独立保留，不将以前管理员关闭的记录自动展示为用户归档。

操作保留任务、模型和工具记录、审批、补丁、checkpoint、业务数据库登记及 Token 用量。删除对话不会返还已经消耗的项目累计额度。状态变更另写审计事件。

项目及其所有对话由项目容器控制显示；项目进入回收站后，需先恢复项目，再恢复其中单独删除的对话。相同文件夹已重新添加为其他工作项目时，旧记录恢复会检查冲突，不会创建两个同时工作的目录授权。

## 权限与运行控制

- 项目管理限管理员；对话操作限对话所有者或管理员，并继续检查项目访问范围及当前身份。
- 归档内容经独立的只读历史接口显示，不能从历史页面继续调用工具、审批、写入文件或发送新轮次；先恢复记录。
- 工具执行、预算入口和任务操作也检查项目与会话状态，不能只靠前端隐藏按钮。
- 执行中、等待审批、正在交付写入、手动写入持有租约或数据库清理未完成时拒绝归档和删除，避免隐藏未结束的操作。
- 项目锁与创建任务、写入和数据库管理共用，归档检查和状态更新不会与新任务创建交叉。
- 历史记录查看只读取平台保存的数据；归档后的本机文件夹被移动时仍可查看历史，不因此读取新的目录。

## 验证

服务端测试覆盖状态往返、项目与对话层级、只读、身份与所有权、工作中保护、实际资源保留、累计用量保留、持久化和 API 限定。

浏览器验收使用独立临时工作台，不操作用户原项目或原对话：完成对话归档、只读查看、恢复、删除到回收站再恢复；完成整个项目归档、从左下角查看、删除到回收站、恢复到归档、再恢复到工作列表。额外验证工作列表为空时归档入口仍可用、原代码内容和消息保持不变。证据：`.temp/library-ui-proof.json`。

回归日志：`.temp/library-full-tests.log`；最终专项日志：`.temp/library-final-tests.log`。
