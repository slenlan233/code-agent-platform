# 后端代码、数据库迁移与集成测试

本版在原有平台的 DockerRunner 中增加 `mysql` 测试配置，不另起一套 Agent。外层任务和审批仍由 LangGraph 管理，规划、编码、审查继续使用共用的 LangChain Agent。

## Docker 在哪里运行

本机实测连接的是 Docker Desktop 的 `desktop-linux` context，端点为 `npipe:////./pipe/dockerDesktopLinuxEngine`。原来的 `mongodb`、`redis8` 没有被启动或修改。

测试容器按任务创建，名称为 `ai-agent-java-it-…`、`ai-agent-mysql-it-…`。结束后自动删除，因此截图中不一定能看到它们。镜像保留在 Images，构建记录在 Builds，实际容器名称、镜像摘要和清理结果保存在任务验证报告中。

## 网络和数据库权限

普通测试继续使用 `--network=none`，这是平台显式设置，并非 Docker Desktop 不能联网。MySQL 测试配置允许后端和数据库在本次专用 internal 网络内互通，gateway 使用 isolated 模式，不发布数据库端口；镜像构建阶段通过网络准备依赖，执行阶段使用离线 Maven。网络行为参考 [Docker 内部网络](https://docs.docker.com/reference/cli/docker/network/create/) 和 [bridge gateway 模式](https://docs.docker.com/engine/network/drivers/bridge/)。

每次创建新的 MySQL `agent_it` 数据库，使用随机临时密码和两个账号：

| 账号 | 权限和用途 |
| --- | --- |
| schema_migrator | 仅在本次库内创建、修改、删除表并维护 Flyway 历史 |
| app_writer | 仅在本次库内 SELECT、INSERT、UPDATE、DELETE |

测试覆盖业务账号确实能写数据，也无法建表或读取 `mysql.user`。初始化 root 账号不交给后端；只用于本次数据库初始化和就绪检查。秘密文件位于平台专用运行目录，报告脱敏，测试结束清理。

这套测试不写入宿主机的 `ai_project2`。原先 MCP 连接的 `ai_project2_agent_ro` 继续负责业务库只读检索；它与这里的后端写入账号用途不同。容器如需连接 Windows 上的服务，应使用 [Docker Desktop 的 host.docker.internal](https://docs.docker.com/desktop/features/networking/networking-how-tos/)，本版验收使用专用数据库，未开启宿主机业务库写入。

## 示例和配置

示例位于 `examples/spring-mysql`，使用 Java 17、Spring Boot 3.5.16、MySQL 8.4 和 Flyway。包含真实 HTTP CRUD、两条版本化 SQL 迁移和六项基础集成测试。迁移和业务使用不同账号；配置方式参考 [Spring Boot 数据库初始化](https://docs.spring.io/spring-boot/how-to/data-initialization.html)。

先准备镜像：

```powershell
docker pull mysql:8.4
docker build --target test-runtime -t ai-agent/spring-mysql-it:0.1 examples/spring-mysql
```

管理员配置需要启用 `allow_mysql_test_network: true`，并把 `ai-agent/spring-mysql-it:0.1` 加入 `sandbox_images`。项目配置使用示例下的 `project-config.json`，其中 `database_test_profile` 为 `mysql`。普通项目默认 `none`。仓库内的文档或模型输出不能自行开启网络。

```powershell
uv run --no-sync ai-agent --config agent-config.local.json project-config 项目ID --file examples/spring-mysql/project-config.json
uv run --no-sync ai-agent --config agent-config.local.json serve --port 8765
```

计划审批展示数据库测试环境；验证报告展示每项 JUnit 结果、实际容器和网络名称，以及清理结果。审批后先在项目副本中验证，最终 Diff 仍需确认后才能写回。
