实际接入需提供目标地址、端口、数据库范围及只读账号，参考 .env.example 和 [原能力迁移与接入](原能力迁移与接入.md)。本轮未猜测或自动连接用户的业务库。

## 项目文件夹和文件去向

侧栏“登记项目 → 选择项目文件夹”可以浏览当前管理员配置的 allowed_roots。界面显示当前读取目录和批准后的写回目录。目录选择器不扩大现有范围，敏感目录、越界路径、上级跳转和目录链接仍被拒绝。普通账号无法浏览目录选择接口。

当前本机允许范围为 D:\学习Java\ai项目\3.xiangmu。扩大到电脑其他位置的改动被自动审批拒绝，因其扩大文件访问范围；需要用户明确授权后另行实施。本轮没有绕过这个限制。

选择文件夹并登记项目后，Agent 从项目范围读取。生成修改先保存为任务中的补丁/产物，验证使用临时隔离副本。最终审批后点击“写入所选项目”才把文件写回登记目录；仅生成、测试和导出不会直接改写原项目。任务页面同时显示本机产物目录，便于定位 Diff、命令和测试输出。

当前演示项目目录为 D:\学习Java\ai项目\3.xiangmu\.temp\platform-preview\demo-project；这是平台创建的示例副本，不是用户自行登记的业务项目。

## Token 统计

任务汇总和逐次模型调用分别显示 input_tokens、cache_read_tokens、uncached_input_tokens、output_tokens。缓存命中来自供应商/SDK 的 input_token_details.cache_read；DeepSeek 适配器会把 prompt_cache_hit_tokens 转为该字段。输入包含缓存命中，故：

```text
输入 = 缓存命中 + 未缓存输入
累计 = 输入 + 输出
```

旧任务从未保存过缓存明细，不能从总输入推算真实命中量；旧记录和供应商缺失字段时显示“未记录”，不会当成 0。新任务会保存供应商返回的真实 0。失败任务也保留已经发生的模型调用及 token 消耗。

真实 DeepSeek 校验记录：输入 8855、缓存命中 6784、未缓存 2071、输出 1590，总量 10445。3 次调用的明细之和与任务汇总一致。这次业务回答因缺少必要引用被 evidence_required 拦截，未宣称任务成功；用量数据独立核验通过，保存在 .temp/cache-tokens-live-report.json。
