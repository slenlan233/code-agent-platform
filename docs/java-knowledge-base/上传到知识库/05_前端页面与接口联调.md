# 前端页面与接口联调

文档编号：JAVA-KB-05｜版本：1.0｜日期：2026-10-27
适用范围：简单 HTML/CSS/JavaScript 前端与 Spring Boot 后端。性质：不依赖前端框架的工程建议。

## 1. 简单项目优先同源

小型演示可以将 `index.html`、CSS、JavaScript 放在 `src/main/resources/static/`，由同一个 Spring Boot 应用提供页面和 `/api/...` 接口。这样通常不需要另起前端开发服务器，也不需要为联调开放跨域。[Spring Boot Servlet Web 应用与静态资源](https://docs.spring.io/spring-boot/3.5/reference/web/servlet.html)

前端请求使用 `/api/todos` 这样的相对路径，随当前网页地址选择主机和端口；不要把某个开发者的 `localhost:8080` 硬编码进所有请求。页面通过应用 URL 打开，而不是直接双击 HTML 文件用 `file://` 访问。

## 2. 先确定接口契约

开始联调前确认方法、路径、输入 JSON、成功响应、错误响应和 HTTP 状态。ID 的类型、时间格式、是否分页和完成状态都要一致。若数据库使用可能超过 JavaScript 安全整数范围的 BIGINT，接口可统一用字符串传输 ID；不能前后端一端当数字、一端当任意字符串。

例如创建接口接收 `{ "title": "买牛奶" }`，返回包含 `id`、`title`、`completed` 的记录；前端不能凭本地数组虚构服务端 ID。

## 3. `fetch` 的错误处理

`fetch` 在收到 400 或 500 时通常仍返回 Response，需要检查 `response.ok`；204 没有 JSON 响应体时不要调用 `.json()`。

```javascript
async function api(path, options = {}) {
  const response = await fetch(path, options);
  if (!response.ok) {
    let message = `请求失败（${response.status}）`;
    try {
      const error = await response.json();
      if (typeof error.message === "string") message = error.message;
    } catch {
      // 错误响应可能不是 JSON，保留通用提示。
    }
    throw new Error(message);
  }
  return response.status === 204 ? null : response.json();
}

async function createTodo(title) {
  return api("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title })
  });
}
```

示例假设非 204 的成功响应均为 JSON；文件下载或其他格式需使用对应读取方式。网络失败和 HTTP 错误都应在调用处捕获并展示。

## 4. 页面状态与持久化

页面至少区分：初次加载、空列表、有数据、提交中、操作失败和成功。发送创建请求时禁用重复提交，成功后采用服务器返回值或重新查询；失败时保留用户输入，不能显示“已保存”。

页面刷新后重新 GET 数据。若需求明确要求 MySQL 持久化，localStorage 可以做可选草稿，不能取代服务端数据库。删除、完成和取消完成都必须真实调用后端，并处理记录已不存在的情况。

## 5. 安全显示用户内容

普通文本通过 `textContent` 或框架的默认文本转义渲染，不把用户标题拼成 HTML。

```javascript
const titleElement = document.createElement("span");
titleElement.textContent = todo.title;
```

不要使用 `innerHTML = todo.title`。需要富文本时必须另行设计可信的消毒策略。错误提示同样当作文本显示，不渲染后端返回的任意 HTML。

## 6. 校验与可访问性

前后端使用同一套标题清理和长度口径。若按 Unicode code point 计数，前端可以用 `Array.from(title).length`；HTML `maxlength` 的计量不能直接替代此规则。后端仍需重新校验。

表单输入提供可识别标签，错误文字关联输入控件。状态提示可使用 `aria-live`；按钮支持键盘操作，完成状态不只靠颜色区分。长标题应换行，移动窗口时不横向溢出。

## 7. 联调检查

依次验证页面加载、创建、列表、完成切换、删除、错误提示、刷新保留、应用重启保留。浏览器控制台不应有未处理异常；Network 面板应显示预期 URL、状态和真实响应。不要仅凭页面截图声称数据库已经保存。

前端 API 行为参考：[MDN Fetch 使用说明](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)。项目中采用的响应包装、分页和错误格式以实际接口契约为准。
