# 自动化测试与验收

文档编号：JAVA-KB-06｜版本：1.0｜日期：2026-10-27
适用范围：Java 17、Spring Boot 3.5.x、Maven、MySQL 8.4。性质：测试设计与结果报告建议。

## 1. 分清验证层次

| 层次 | 能证明什么 | 单独不能证明什么 |
| --- | --- | --- |
| 编译、打包 | 源码和依赖可以构建 | 接口和数据库行为正确 |
| 单元测试 | 业务规则在受控输入下正确 | 真实 MySQL SQL 与迁移正确 |
| 数据库集成测试 | 真实数据库访问、约束和迁移正确 | 网页操作和本机启动正常 |
| HTTP 集成测试 | 请求、响应与真实持久化连通 | 所有浏览器交互正确 |
| 本地启动与浏览器验收 | 实际环境和页面主要流程可用 | 所有异常分支和生产负载可用 |

模拟 Repository 适合部分单元测试，但“真实 MySQL 持久化”验收不能全部依赖模拟接口或 H2。尽可能覆盖真实数据库版本的行为。

## 2. Maven 测试执行

可将单元测试交给 Surefire，集成测试交给 Failsafe；使用 Failsafe 时在 POM 中绑定 `integration-test` 和 `verify` goals，并遵循或配置其测试命名规则，例如 `TodoApiIT`。不能只把类名改成 IT 就假定 Maven 会自动执行它。

```text
mvn -B test
mvn -B verify
```

调用 `verify` 能让配置好的集成测试运行到结果校验阶段；仅调用 `integration-test` 可能绕过后续校验和清理阶段。[Maven Failsafe 官方说明](https://maven.apache.org/surefire/maven-failsafe-plugin/index.html)

`target/surefire-reports/` 和 `target/failsafe-reports/` 中检查实际测试数、失败、错误和跳过情况。构建退出码为 0 但测试数为 0，不能当作“全部测试通过”。不使用 `-DskipTests` 冒充完整验收。离线 `-o` 仅在依赖已缓存时使用。

## 3. 隔离真实数据库

测试需要临时 MySQL，可使用平台的数据库测试环境或 Testcontainers；选择一种生命周期管理方式，避免两套管理器互相争抢容器和端口。

测试环境配置必须与业务环境分离。使用明确的 test profile 及测试专用变量，并在运行前检查其实际指向。用于清表或建删库的账号只能作用于隔离测试库。

容器的 `127.0.0.1` 指向容器自身。平台可以通过专用 Docker 网络连接测试 MySQL；访问宿主机数据库则要单独配置网络与授权，不应擅自改为访问已有业务库。

Docker 未启动或数据库不健康时应报告环境失败；不要悄悄在宿主机运行有副作用的替代测试，不要改连业务库让测试变绿。

## 4. CRUD 参考用例

下面的 Todo 用例可作为简单项目基线：

| 场景 | 应验证的结果 |
| --- | --- |
| 空库启动 | Flyway 建表成功，查询返回空列表 |
| 新增普通中文标题 | 返回 201，记录确实写入数据库 |
| 新增含 emoji 的标题 | 编码和读取正确，长度口径一致 |
| 标题为空或全空白 | 返回 400，不产生记录 |
| 标题恰好达到上限及超出一位 | 边界行为与接口契约一致 |
| 标记完成、取消完成 | 状态按请求值更新并持久化 |
| 查询或更新不存在 ID | 按约定返回 404 |
| 删除已有记录 | 返回 204，再查询确实不存在 |
| 非法 JSON 或字段类型 | 返回明确信息，不暴露堆栈 |

需要证明通过真实 HTTP 与 MySQL 的端到端链路时，可使用随机端口启动应用、调用 HTTP 客户端，并通过再次读取或受控数据库断言核实持久化。仅检查 Service 返回对象不足以证明写入。

## 5. 重启持久化验收

1. 使用隔离验收库启动应用，创建一条带唯一标识的记录并保存 ID。
2. 刷新页面或重新发起 GET，确认记录仍存在。
3. 停止应用进程，保留该数据库及其数据。
4. 使用同一份连接配置重启应用，确认记录仍存在且状态正确。
5. 验收结束后清理该隔离库，记录实际做过的步骤。

重启时不得更换为全新测试容器，否则不能验证“同库重启后保留”。也不要把“应用重启”混同为“删除数据库后重建”。

## 6. 修复与复测

失败先分类：源码行为错误、迁移错误、权限错误、依赖下载、Docker 服务或本地端口。保留命令、退出码和关键错误，修复后重跑相关检查。若只重跑了一部分，应明确报告范围，不能把以前的结果套到新补丁上。

## 7. 交付报告

报告包括环境与版本、执行命令、退出码、测试数、跳过数、数据库类型、实际验证范围和未验证项。区分测试通过、AI 代码检查、人工接受和文件实际写入状态；它们是不同事实。

示例：`mvn -B verify` 退出码 0，单元测试 5 项、MySQL HTTP 集成测试 9 项通过；尚未进行 Windows 本地启动与浏览器验收。示例数字仅展示报告格式，不代表当前任何项目的真实结果。
